## Standard emoji

Beyond the curated set above, **any standard emoji** renders on hires
(scaled) displays — typed as real unicode (🚀) in widget text, or as its
CLDR-short-name slug (`:rocket:`). ~1,360 emoji ship in a lazy-loaded
pack derived from [Noto Emoji](https://github.com/googlefonts/noto-emoji)
(Apache 2.0). Skin-tone variants render as their base emoji; multi-person
(ZWJ) sequences fold to their first member; letter flags are not included.

Standard emoji work everywhere curated emoji do — message text, `two_row`
rows, gif/image text overlays, inline value tokens, and through the
[`flair.fisheye`](/concepts/animations/#flairfisheye-flair-pack) lens
(sprites swell through the center and compress at the edges just like
letters). Each of the flower emoji (🌸 🌺 🌷 🌹 💐 🌼) renders its own
sprite — a rose is a rose, a bouquet is a bouquet — while the `:flower:`
slug keeps the curated blossom.

**Scale-1 displays (smallsign):** standard emoji are hires-only — unicode
is stripped from the text, and `led-ticker validate` warns if a config
uses a hires-only `:slug:` at scale 1. The curated 8×8 set above is the
smallsign emoji set.

## Your own images as emoji

Any local PNG or GIF can become a custom emoji: declare it with a
`[[source]]` block and embed its `:id:` token anywhere text renders —
mid-sentence, in titles, on two-row cards.

```toml
[[source]]
type = "image"
id = "cart.logo"
path = "assets/cart-logo.png"

[[playlist.section.widget]]
type = "message"
text = "HALAL CART :cart.logo: OPEN LATE"
```

**Where the file goes.** Drop it in `config/assets/` next to your
`config.toml` (the same folder the [gif](/widgets/gif/) and
[image](/widgets/image/) widgets use — it's mounted into Docker
automatically). Getting the file onto the Pi is up to you today: `scp`, a
network share, or a USB stick. The web UI can't upload assets yet — that's
planned, not implied.

**Naming.** Use a dotted id (`cart.logo`, `me.parrot`). The standard-emoji
pack owns ~1,400 bare English words (`fire`, `taco`, `star` are all real
slugs), and a colliding id is a validate error — the dotted form sidesteps
the whole problem.

**Sizing.** On scaled displays (bigsign, longboi) the image renders as a
32-pixel-tall sprite, width proportional up to 128 px. On a scale-1 sign
(smallsign) it auto-downscales to 8×8 — recognizable for simple marks,
approximate for detailed art; `led-ticker validate` reminds you.

**Animated GIFs animate** on scaled displays — frames advance at the
GIF's own timing, in phase everywhere the slug appears, even mid-scroll
or during a transition. Keep GIFs at 24 frames or fewer for comfort
(`led-ticker validate` warns above that; more than 60 frames is refused).
On a scale-1 sign the sprite shows its first frame, static.

If something's wrong (missing file, name collision), the sign never goes
dark: the bad source is skipped with a logged error and the token renders
as literal text. Run `led-ticker validate` to catch it before deploy.
