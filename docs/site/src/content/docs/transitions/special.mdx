The special family covers transitions that don't fit the push / wipe / sprite shapes. Most are full-canvas effects (`color_flash`, `fade`, `dissolve`, `split`) or single-frame cuts; `scroll` is the odd one out — a continuous-scroll bridge that connects two widgets with a bullet separator instead of pausing for a transition.

The scroll separator is a small white dot by default. Recolor it (e.g. to tone
it down on bright content) with `separator_color` on the transition table —
`transition = { type = "scroll", separator_color = [80, 80, 80] }` — accepting
the same values as a widget `font_color`, including `"rainbow"`. (This is the
scroll _transition's_ separator and is distinct from the ticker-mode section
`separator_color`, which colors the loop separator between ticker widgets.)

To use a character instead of a dot, set `separator`:
`transition = { type = "scroll", separator = "·" }`.
Include surrounding spaces for padding (e.g. `separator = ' · '`); set
`separator_font` / `separator_font_size` only for a non-default font.
`separator_size` sets the dot's pixel size (default 2); it has no effect when a glyph separator is set.

## Fade

`fade` crossfades the outgoing widget into the incoming one: both are drawn once, then blended frame by frame, so text, images, borders and `bg_color` all soften through each other instead of cutting. Set `transition_color` and it becomes a dip: the outgoing fades to that colour over the first half and the incoming rises out of it over the second (`[0, 0, 0]` is the classic dip to black).

- Bare `fade` is the crossfade; `transition_color = [r, g, b]` is the dip. An empty list (`[]`) is the crossfade too, not a default colour.
- In a `random` / `auto` pool, members inherit the slot's `transition_color`, so `{ type = "random", transition_color = [255, 0, 0] }` makes the pooled fade dip through red. Put the colour on the entries that want it instead: `pool = [{ type = "wipe_left", transition_color = [255, 0, 0] }, "fade"]`.
- `fade` runs at least 8 frames (0.4 s at the default 20 fps); a shorter `duration` is stretched to that floor. Raise `transition_fps` for a faster fade.
- Known limit, shared with every transition: a `gif` / `image` widget's text overlay, border and background are painted by its play loop, not its compositing draw, so they cut at the fade's endpoints while the image itself fades.
- Bigsign: the panel's brightness curve has a short dead zone near black, so the very end of a fade-in can pop. If it shows, try `pwm_bits = 9` or `10` in `[display]` (more refresh cost; see the hardware page).

## Pools (`random` / `auto`)

Bare `transition = "random"` (or `"auto"`) uses the default pool and the section's duration. The table form picks the members:

```toml
transition = { type = "random", exclude = ["color_flash", "dissolve"] }
# or, picking the members yourself:
transition = { type = "random", pool = [
  "wipe_in", "push_up",
  { type = "flair.splitflap.forward", duration = 3.0 },
  { type = "flair.fireworks", duration = 2.0, colors = [[255,110,0],[255,190,40]] },
] }
```

- `pool`: a list of transition names or tables (`type` plus `duration`, `transition_color`, and a plugin's own knobs). `exclude`: names to drop. A pool needs at least two distinct members; `cut`, `scroll`, the four core wrappers, and `random` / `auto` themselves cannot be members. Plugin transitions join only through an explicit `pool`.
- `duration` is the one _runner_ knob a member can override per firing — plugin effects usually want their own (a 3 s split-flap under a 0.5 s section is a blur). `easing` and `transition_fps` stay section-level.
- Members inherit the slot's `transition_color` (what the `transition` / `entry_transition` / `widget_transition` table itself carries); `transition_colors` reaches only plugin members that take a colour list (core members take a single colour).
- Slots that run it: `between_sections` (or `[transitions] default` standing in for it when `between_sections` is omitted), and a section's `transition`, `entry_transition`, `widget_transition`. Within-section swaps never read `default`.
- "Never twice in a row" is per slot: a section's entry and widget slots keep separate pickers, so the same effect can appear on an entry and the next widget swap. Several sections each writing `transition = "auto"` start aligned on the first pass, then drift apart as their widget counts differ; for one cycle across sections use `between_sections = "auto"`.
- `led-ticker validate` checks pools (rule 73): unknown or excluded members, bad durations and colours, pools that shrink below two, and a `default = "random"` that a typed `between_sections` makes dead.
