The flair pack (`led-ticker-flair`) ships two categories of transition: **homage sprite-trails** — pixel-art characters that cross the panel — and **text-effect transitions** that manipulate the outgoing content itself. Both are referenced by their namespaced slug, e.g. `transition = "pokeball.forward"` or `transition = "flair.spinout"`.

## Homage transitions (flair pack)

The four homage families — **nyancat**, **pokeball**, **pacman**, and **sailor_moon** — ship together in the `led-ticker-flair` package (one install, four entry points, each with `.forward`, `.reverse`, and `.alternating` variants).

### Install

Add one line to `config/requirements-plugins.txt` (copied from `config/requirements-plugins.example.txt`):

```text
led-ticker-flair
```

One install registers all four families. See [Plugins](/plugins/) for the install flow.

A bare `transition = "nyancat"` (the pre-plugin spelling) raises a config-load error pointing at the namespaced `nyancat.forward` slug — the namespaced form is what the flair pack registers.

:::note[Existing configs need no change]
The type strings (`nyancat.forward`, `pokeball.alternating`, etc.) are unchanged — only the install source consolidates. Configs already using these transitions keep working as-is. If you previously pinned individual family tags (e.g. `@nyancat-v0.1.0`), those installs continue to work; switch to the single flair line at your convenience.
:::

## Hires

`nyancat.forward` and `pokeball.forward` auto-activate hi-res sprites whenever the canvas is at `default_scale > 1` — that is, any big / scaled sign (see [Display](/concepts/display/)), typically a bigsign-style build. The hi-res variants are noticeably more detailed and read better at distance:

- **nyancat** — animated webp Nyan Cat sprite at native physical resolution
- **pokeball** — rolling pokeball with animated run-cycle sprite

The `sailor_moon` and `pacman` families keep their 8-bit look at all scales — the chunky aesthetic is part of the design.

## Other plugin sprites

The rolling-**baseball** family (`baseball.roll`, `baseball.roll_reverse`, `baseball.roll_alternating`) ships with the **[baseball](https://github.com/JamesAwesome/led-ticker-plugins/tree/main/plugins/baseball)** package in the led-ticker-plugins monorepo, alongside that package's MLB widgets and `:baseball.ball:` emoji. Install it via `config/requirements-plugins.txt` (see [Plugins](/plugins/)) to use it.

## Text-effect transitions (flair pack)

### `flair.spinout` (flair >= 0.3.0, core >= 4.6)

`flair.spinout` spins the outgoing widget's content out of view — starting at rest, then accelerating — before cutting to the incoming widget. Unlike a sprite trail, nothing crosses the panel; the content itself rotates and disappears. Transition duration follows `[transitions] duration` (default 0.5 s; sprite-style durations of 1.0–1.5 s look best for a full revolution or two).

<DemoGif
  src="/demos-pinned/transition-flair-spinout.gif"
  caption="`flair.spinout` — outgoing text accelerates and spins out before the incoming widget appears"
/>

#### Install

`flair.spinout` is part of the same `led-ticker-flair` package as the homage sprite-trails:

```text
led-ticker-flair
```

One install registers all flair transitions and animations. See [Plugins](/plugins/) for the install flow.

#### Minimal config

<TomlExample
  title="Minimal"
  code={`[transitions]
default = "flair.spinout"
duration = 1.0

[[playlist.section]]
mode = "slideshow"
hold_time = 3.0

[[playlist.section.widget]]
type = "message"
text = "SPIN OUT"
center = true
font_color = [0, 220, 255]

[[playlist.section]]
mode = "slideshow"
hold_time = 2.5

[[playlist.section.widget]]
type = "message"
text = "AND CUT"
center = true
font_color = [80, 255, 80]`}
/>

#### Knobs

| Knob          | Default | Notes                                                   |
| ------------- | ------- | ------------------------------------------------------- |
| `revolutions` | `2`     | Integer >= 1. Full turns before the content disappears. |
| `direction`   | `"cw"`  | `"cw"` (clockwise) or `"ccw"` (counter-clockwise).      |

Set knobs via an inline table on `[transitions] default` or on the section's `transition` field:

```toml
[transitions]
default = {type = "flair.spinout", revolutions = 1, direction = "ccw"}
duration = 1.0
```

#### Behavior notes

- **Background color holds.** The outgoing section's `bg_color` fills the panel for the entire spin duration — the background never flashes or drops to black mid-transition.
- **Scrolled text spins from its parked position.** If the outgoing widget had been scrolling, `flair.spinout` picks up at the position where the text stopped (the same `outgoing_scroll_pos` continuity used by the push family).
- **Colors freeze during the spin.** Animated `font_color` providers (`rainbow`, `color_cycle`, `shimmer`) are paused for the outgoing widget while it spins, consistent with how transitions pause frame-aware effects in general.
- **Pairs with `flair.propeller`.** Use `flair.spinout` as the inter-widget or between-sections transition alongside `animation = "flair.propeller"` on `message` widgets for a full spin-in / spin-out cycle. See [flair.propeller → Pairing with flair.spinout](/concepts/animations/#pairing-with-flairspinout).

### `flair.fireworks` (flair >= 0.7.0, core >= 4.10)

`flair.fireworks` holds the outgoing widget while staggered firework bursts launch as rising streaks from the bottom edge, then open into black "burn-through" holes ringed by radial spoke trails — an asterisk of bright white heads and fading colored tails, not a ring outline. Past the halfway point every burst's hole blooms in lockstep toward full-panel coverage, revealing the incoming widget through the expanding circles and blacking out everything outside their union, until embers fade and the whole panel cuts to the incoming section. Transition duration follows `[transitions] duration` — about 1.2 s gives the bursts room to stagger, open, and bloom without feeling rushed.

<DemoGif
  src="/demos-long/transitions-fireworks.gif"
  caption="`flair.fireworks` — staggered bursts open over the outgoing widget, then bloom to reveal the incoming widget"
/>

#### Install

`flair.fireworks` is part of the same `led-ticker-flair` package as the homage sprite-trails and `flair.spinout`:

```text
led-ticker-flair
```

One install registers all flair transitions and animations. See [Plugins](/plugins/) for the install flow.

#### Minimal config

  title="Minimal"
  code={`[transitions]

/>

With knobs, set via an inline table on the section's `transition` field (or on `[transitions] default`/`between_sections`):

<TomlExample
  title="With knobs"
  code={`[[playlist.section]]
transition = {type = "flair.fireworks", bursts = 3, colors = [[255, 60, 60], [0, 220, 220]]}`}
/>

#### Knobs

| Knob     | Default                  | Notes                                                                                                                                                                                                                                                                                                                                                                                           |
| -------- | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bursts` | size-adaptive (3-6)      | Number of firework bursts. Auto-picked from the panel's width-to-height ratio when omitted — wider panels get more bursts (smallsign: 5, bigsign: 4, longboi: 6) — or set explicitly in `[2, 8]`.                                                                                                                                                                                               |
| `colors` | 8-color built-in palette | List of `[r, g, b]` triples, cycled across bursts in order. From core **4.11** the standard `transition_colors` field works too (it reaches any plugin transition that declares a `colors` parameter, in per-section `transition =` and table-form `between_sections` — the same places built-in transition colors apply); a `colors` key written directly in the transition table always wins. |
| `seed`   | `None` (OS entropy)      | Fixes the RNG for reproducible bursts — useful for regression tests and reproducible demo GIFs. Not a promise that the same seed plans the same sequence forever: a re-fire of the same running instance continues drawing from that same RNG stream, so consecutive firings on a live sign still vary. Leave unset for a real deploy.                                                          |

#### Behavior notes

- **Size-adaptive by default.** Burst count, radius, and stagger timing are all derived from the panel's actual width/height at draw time — the same `transition = "flair.fireworks"` line looks right on smallsign, bigsign, and longboi without per-sign tuning.
- **Two-phase design, painted through black.** There is no `GetPixel` on real hardware (the framebuffer stores pre-computed GPIO bitplane data, not readable RGB), so nothing can be composited from a previous frame — every frame is drawn from scratch from the widgets plus burst geometry. Phase one (`t < 0.5`) plays over the outgoing widget; phase two (`t >= 0.5`) switches to the incoming widget and blacks out everything outside the union of the (still-growing) burst circles, guaranteeing full coverage by `t == 1.0` regardless of any individual burst's stagger.

### `flair.stickers` (flair >= 0.9.0, core >= 4.18)

`flair.stickers` sticker-bombs the panel: emoji "stickers" pop on one at a time in a random order over the outgoing widget until they fully cover it at the halfway point, then pop off in an independent random order, revealing the incoming widget in the gaps. Each sticker sits on a tilted die-cut card so the wall reads as stickers on glass. Pass `emoji = ["taco"]` for a themed wall of one emoji, a list for a mix, or omit it for a random assortment. Since core 4.21.0 the drawable set includes the ~1,360-emoji [standard-emoji pack](/assets/emoji/#standard-emoji), so random mode (flair >= 0.13.0) samples up to **12 distinct emoji per firing** and builds the wall from those — wildly different stickers every firing, a coherent wall within one.

<DemoGif
  src="/demos-pinned/transition-flair-stickers.gif"
  caption="`flair.stickers` — a wall of taco cards buries the outgoing widget, then peels away to reveal the incoming one"
/>

#### Install

`flair.stickers` ships in the same `led-ticker-flair` package as the sprite-trails and the other text-effect transitions:

```text
led-ticker-flair
```

One install registers every flair transition and animation. See [Plugins](/plugins/) for the install flow.

#### Minimal config

<TomlExample
  title="Themed taco wall"
  code={`[[playlist.section]]
mode = "slideshow"
hold_time = 3.0
transition = {type = "flair.stickers", emoji = ["taco"]}

[[playlist.section.widget]]
type = "message"
text = "TACO"
center = true
font_color = [255, 190, 0]`}
/>

#### Knobs

| Knob      | Default                     | Notes                                                                                                                                                                                                                                                                                                                                                          |
| --------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `emoji`   | omitted (random assortment) | List of emoji slugs (no colons), e.g. `["taco"]` or `["sun", "moon", "star_yellow"]`. A single-item list is a themed wall; a list mixes (never capped); omitting it samples ≤ 12 distinct slugs per firing from the full drawable set (~1,360 with the standard-emoji pack) and draws each sticker from those. An unknown slug fails at `led-ticker validate`. |
| `backing` | `"card"`                    | Sticker body. `"card"`: tilted black card with a white rim — the only mode that fully covers the panel at the midpoint. `"shadow"`: black silhouette halo, no card. `"none"`: bare sprites. Shadow/none read as an emoji **swarm** — gaps stay visible, by design.                                                                                             |
| `seed`    | `None` (OS entropy)         | Fixes sticker positions, angles, and pop-on/off order for reproducible runs. Leave unset for a real deploy (every firing varies).                                                                                                                                                                                                                              |

#### Behavior notes

- **The card is what guarantees full coverage.** Each `"card"` sticker is squared to its grid cell, so a jittered grid of cards covers the panel completely at the midpoint regardless of the emoji's shape. `"shadow"` and `"none"` deliberately trade that guarantee for a lighter, see-through swarm.
- **Only real slugs.** A typo like `emoji = ["fire"]` (there is no `fire` slug) fails at config-load with the bad slug named — see [Emoji](/assets/emoji/) for the full list.
- **Random mode is chaos across firings, coherence within one.** With no `emoji`, each firing samples up to 12 distinct slugs from the full drawable set and builds the wall from those — one firing might be lobsters, dice, and hearts; the next guitars, planets, and pizza. Explicit `emoji = [...]` lists are never capped.

### `flair.poker` (flair >= 0.10.0, core >= 4.18)

`flair.poker` deals the panel in with card suits. Rainbow ♥ ♦ ♣ ♠ glyphs pattern in over the outgoing widget, then each one emits **suit-shaped** rainbow ripple rings — an expanding heart emits heart-shaped rings, a club club-shaped ones — that wash the incoming widget in until the panel is covered. #### Knobs

| Knob    | Default             | Notes                                                                                                                                                  |
| ------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |

#### Behavior notes

- **The reveal is against black.** Like `flair.fireworks`, the second half reveals the incoming widget inside the ripple wakes against black (hardware can't composite two widgets — there is no `GetPixel`), then covers the whole panel by the end. The suit glyphs and their rings share one shape function, which is what lets the ripples take each suit's outline.
- **Single-suit is a theme, all-suits is a shuffle.** `suits = ["hearts"]` gives a wall of heart ripples; omitting `suits` mixes all four across the grid.

Section backgrounds (`bg_color`) show inside the gap from the first sliver.
- **No warm-up.** Every frame is a pure function of the transition's progress; the first firing after boot costs the same as every other.

### `flair.laser` (flair >= 0.15.0, core >= 4.31)

`flair.laser` writes the sign the way a commercial LED message board's "laser" effect does: beams reach in from one panel edge, erase the old content pixel by pixel in a back-and-forth raster, then write the new content the same way. Each beam is a one-pixel bar from the edge to the pixel it is working on, in that pixel's own colour — a red headline is erased by red beams, a rainbow one by rainbow beams. It works on every widget type, because the content is snapshotted as pixels rather than text. Six variants, named by the edge the beams come from: `flair.laser.top`, `.bottom`, `.left`, `.right`, `.alternating` (top → right → bottom → left, one per firing) and `.random`.

#### Knobs

| Knob         | Default                          | Notes                                                                                                                                                                                                                                                               |
| ------------ | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `beams`      | `3`                              | Number of independent beams. The lit content is split into that many equal slices (across the panel for top/bottom, down it for left/right); each beam erases then writes its own slice at its own constant speed. `1` is the classic single back-and-forth raster. |
| `write_from` | omitted (same edge as the erase) | `"top"` / `"bottom"` / `"left"` / `"right"` / `"opposite"` — the edge the **write** phase's beams come from. The variant names the erase edge. `"opposite"` mirrors whatever edge is erasing, so it composes with `.alternating` and `.random`.                     |

The erase direction is **not** a knob — pick the variant. The beam colour is always the content's own colour.

#### Behavior notes

- **Two phases, one timeline.** The transition `duration` covers both erase and write; time splits in proportion to how many lit pixels each side has, so a short message erases quickly and a long one takes longer. An empty outgoing (boot, wake from dark) goes straight to writing. All beams finish together at 95 % of the duration; the last 5 % is the usual snap to the incoming widget.
- **Backgrounds.** The section `bg_color` is painted by the engine, never by the widget, so it is never lasered: erased pixels show the old background, and the panel switches to the new background the moment the first beam starts writing. A widget's own fill (`image`/`gif` `bg_color`, `two_row` band colours) is content and gets written pixel by pixel.
- **Snapshot, not a live draw.** Both widgets are drawn once per firing into an offscreen raster at physical resolution; the beams work from that, so a clock ticking over mid-transition can't leave stray pixels behind. A live incoming (a clock with seconds) is written showing its time at the start and jumps to live on the final frame. On the bigsign a logical pixel is a 4×4 block written in four passes of four, with a one-real-pixel beam.
- **Cross-scale sections.** When the next section uses a different `scale`, the incoming content is written at the outgoing scale and pops to its own size on the final frame — the same accepted limitation as `flair.fairy`, `flair.lightning` and `flair.fireworks`.

### `flair.accordion` (flair >= 0.17.0, core >= 4.32)

`flair.accordion` plays the outgoing content like a dealer spreading a deck of cards: the message bunches into an overlapping stack that slides off one edge, then the incoming stack slides in from the far edge and fans out into place. Overlap is real occlusion, like a card fan, and the spread is tied to travel, so the content is tightest at the panel edge and reaches its full spacing exactly on arrival. It works on every widget type, because the content is snapshotted as pixels rather than text. Two variants:

| Type                      | Motion                                                                                                     |
| ------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `flair.accordion.sweep`   | Cards are scooped up one by one and the stack is pushed off; the incoming stack is laid down card by card. |
| `flair.accordion.stretch` | The content moves as one piece, squeezing shut as it leaves and opening up as it lands.                    |

Each has an `.alternating` variant (flair >= 0.18.0) that flips sides every time it fires: left, then right, then left. A firing cut off partway still counts, so the next one switches.

| Type                                  | Motion                                     |
| ------------------------------------- | ------------------------------------------ |
| `flair.accordion.sweep.alternating`   | `flair.accordion.sweep`, flipping sides.   |
| `flair.accordion.stretch.alternating` | `flair.accordion.stretch`, flipping sides. |

#### Knobs

| Knob        | Default  | Notes                                                                                       |
| ----------- | -------- | ------------------------------------------------------------------------------------------- |
| `direction` | `"left"` | `"left"` exits left and enters from the right; `"right"` mirrors it (`"left"` / `"right"`). |

On the `.alternating` variants, `direction` sets the side of the first firing; after that the side flips every firing.

Recommended: `duration = 2.0` with `easing = "ease_in_out"`.

#### Behavior notes

- **Borders stay still.** A bordered widget keeps its border ring in place, painted over the cards; the content moves, including any text that overlaps the ring.
- **Two-row widgets.** Each row gets its own deck; the decks move in lockstep. Each pixel goes with the row that draws it, so a descender, an i or j dot, or a `text_y_offset` nudge stays with its own row; where the two rows overlap, a pixel both rows draw goes to the band it sits in. (A two-row widget with a `background` is the exception: see below.)
- **Background effects.** A widget with a `background` effect (and full-panel `image`/`gif` widgets) has no gaps to fan, so it slides as a single card (both rows of a `two_row` included).
- **Image/gif widgets.** Core draws only the picture during a transition (no border, no text overlay), so a bordered or captioned image gets no ring and no row split: the picture moves as one deck.
- **Backgrounds.** The section `bg_color` is painted by the engine, never by the transition. The panel switches to the new section's background at the halfway point, on the same frame the incoming deck starts to slide in, with no black flash. The short empty beat just before it (which can be zero frames on a fast transition) still shows the outgoing background.

### `flair.interlock` (flair >= 0.19.0, core >= 4.32)

`flair.interlock` is the BetaBrite / Alpha "Interlock" special mode. The panel is cut into thin strands. Alternate strands of the old message slide off toward opposite edges, then the new message's strands race in from opposite edges and mesh together. Each strand keeps one direction for the whole transition, like a conveyor belt. It works on every widget type, because the content is snapshotted as pixels rather than text. Four variants:

| Type                          | Strands                      | Even strands travel          | Odd strands travel |
| ----------------------------- | ---------------------------- | ---------------------------- | ------------------ |
| `flair.interlock.horizontal`  | rows (the Alpha classic)     | left → right                 | right → left       |
| `flair.interlock.vertical`    | columns                      | top → bottom                 | bottom → top       |
| `flair.interlock.alternating` | cycles horizontal → vertical | one axis per firing          |                    |
| `flair.interlock.random`      | a random axis and direction  | never the same twice running |                    |

#### Knobs

| Knob     | Default | Notes                                                                                                                                         |
| -------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `strand` | `1`     | Strand thickness in logical rows (or columns), a positive whole number. On the bigsign at `default_scale = 4`, one logical row is 4 LED rows. |

`.alternating` and `.random` pass `strand` through to every variant. The shortest transition is 24 frames (1.2 s at the default 20 fps); `duration = 1.5` reads well.

#### Behavior notes

- **Travel is sized to the content.** The strands travel just far enough to clear the content off the panel. The old message has just gone at the halfway point and the new one starts arriving right after, so the halfway frame is the only blank one, even for short centred text.
- **`.alternating` and `.random` cycle on `between_sections`.** Set them on `[transitions] between_sections`, as the demo does, to get a different variant at each section change. A section's own `transition` is rebuilt every time that section starts, so as a section entry it fires the first variant (horizontal) every time.
- **Borders move with the content.** A bordered widget's ring is cut into strands along with everything else.
- **Backgrounds.** The panel switches to the new section's `bg_color` at the halfway point, on that blank frame, so there's no visible cut.
- **Cross-scale sections.** The incoming content is snapshotted at the halfway point at its own scale, so it meshes in at its native size.
- **Letterboxed sections** (for example `scale = 2, content_height = 16` on a 64-row panel). Strands are cut from the content rows; any lit rows in the blank bands above and below travel with the nearest edge strand.

### `flair.blinds` (flair >= 0.19.0, core >= 4.32)

`flair.blinds` is the venetian-blind (or "shutter") reveal found on modern LED sign controllers. The panel is cut into equal slats, and every slat opens at the same moment in the same direction, revealing the new message through the old one. There's no sweep line; for that look use the [wipe family](/transitions/wipe/). It works on every widget type. Six variants, named by the direction each slat opens:

| Type                       | Slats                           | Each slat opens              |
| -------------------------- | ------------------------------- | ---------------------------- |
| `flair.blinds.down`        | horizontal                      | top → bottom                 |
| `flair.blinds.up`          | horizontal                      | bottom → top                 |
| `flair.blinds.right`       | vertical                        | left → right                 |
| `flair.blinds.left`        | vertical                        | right → left                 |
| `flair.blinds.alternating` | cycles down → right → up → left | one direction per firing     |
| `flair.blinds.random`      | a different direction each time | never the same twice running |

#### Knobs

| Knob    | Default | Notes                                                                                                                                                                                 |
| ------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `slats` | `8`     | Number of slats, a positive whole number. Slats are whole logical pixels, the last one takes any remainder, and the count is capped so every slat is at least one logical pixel wide. |

On `.alternating` and `.random`, an explicit `slats` applies to every direction. The shortest transition is 16 frames (0.8 s at the default 20 fps); 1.0–1.5 s reads well.

Horizontal slats split the 16 logical rows of a standard section, on the smallsign and on the bigsign at `default_scale = 4` alike. The default 8 slats are 2 rows each, so each slat has only one in-between step. Use `slats = 4`, as the demo does, for a smoother open.

#### Behavior notes

- **`.alternating` and `.random` cycle on `between_sections`.** Set them on `[transitions] between_sections`, as the demo does, to get a different direction at each section change. A section's own `transition` is rebuilt every time that section starts, so as a section entry it opens downward every time.
- **Backgrounds.** The opened part of each slat shows the new section's `bg_color`, and the rest still shows the old one.
- **Cross-scale sections.** The old and new messages share the panel for the whole transition, so incoming content renders at the outgoing scale and pops to its own size on the final frame. `flair.laser`, `flair.fairy` and `flair.lightning` have the same limitation.
- **Letterboxed sections** (for example `scale = 2, content_height = 16` on a 64-row panel). Horizontal slats split the content rows, so they're all the same size. The blank band on the side a slat opens from opens with that slat's first row; the band on the far side opens when its slat finishes.

### `flair.snow` (flair >= 0.20.0, core >= 4.33)

`flair.snow` swaps content behind a flurry. A ragged front of snow sweeps down the panel with flakes falling ahead of it; above the front you see the incoming widget, below it the outgoing content is still showing. The flurry builds in the middle of the transition and thins to nothing before the final cut. It works on every widget type, because the content is snapshotted as pixels rather than text. There is one variant, `flair.snow`.

`flair.snow` is also a [background effect](/concepts/backgrounds/) (`background = "flair.snow"`), which drops snow behind a widget's content for as long as it is on screen. The transition and the background share the flake shapes but are configured separately.

#### Knobs

| `flake`   | `"dot"`           | `"dot"` (one LED), `"plus"` (a 5-LED cross), `"flake"` (a hand-drawn 5×5 snowflake), or an [emoji slug](/assets/emoji/) with an 8×8 low-res form. Hi-res-only slugs are refused. `:snow:` is a rain-cloud icon, not a flake. |
| `density` | `6.0`             | Flakes per 1000 panel pixels at the peak of the flurry, from just above 0 up to 50.                                                                                                                                          |

- **Backgrounds.** The section `bg_color` doesn't follow the front: the outgoing background stays until the final cut, then the new section's background appears. Adjacent sections with different `bg_color` pop at that cut.
- **Cross-scale sections.** The incoming content renders at the outgoing scale until the final frame, then pops to its own size. `flair.laser` and `flair.fairy` have the same limitation.

### `flair.splitflap` (flair >= 0.21.0, core >= 4.33)

`flair.splitflap` is the Solari split-flap departure board. Every character of the old message is a flap hinged across its middle: the top half falls over to reveal the next character, then the bottom half folds down after it. Each character clatters through a few in-between characters before landing on the new one, and the characters settle one after another in a ripple. The flaps flip in place, in your widget's own font, size and colour, on the normal panel background (no tiles). Four variants, named by the ripple:

| Type                          | Characters settle                     |
| ----------------------------- | ------------------------------------- |
| `flair.splitflap.forward`     | left → right                          |
| `flair.splitflap.reverse`     | right → left                          |
| `flair.splitflap.alternating` | forward, then reverse, one per firing |
| `flair.splitflap.random`      | in a random order, fresh each firing  |

#### Knobs

| Knob      | Default | Notes                                                                                                                                                                                                                                                                          |
| --------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `flips`   | `3`     | In-between characters each position clatters through before it lands, a whole number from 0 to 12. They're picked from characters about as wide as that position, so a wide letter never spills onto its neighbours. `0` flips straight from the old character to the new one. |
| `stagger` | `0.5`   | Share of the transition spent rippling across the message, from 0 to 0.9. `0` flips every character together; higher values spread them out (and make each flap quicker).                                                                                                      |

`.alternating` and `.random` accept both knobs too and pass them to each direction.

It's meant to be watched: give it about `duration = 3.0`. The shortest transition is 36 frames (1.8 s at the default 20 fps).

#### Behavior notes

- **In-between characters are borrowed.** They're cut from the two messages on screen, so they always match your font and colour, but they're a shuffle of those characters, not an A-B-C run. A message with only one or two distinct characters gets fewer in-between flips.
- **Unchanged characters stay put.** A character that is identical, in the same place, in both messages doesn't flip.
- **Different lengths.** Extra positions flip from blank, or to blank.
- **`.alternating` cycles on `between_sections`.** Set it on `[transitions] between_sections` to switch ripple direction at each section change. A section's own `transition` is rebuilt every time that section starts, so as a section entry it ripples forward every time.
- **Two-row widgets** flip each row on its own hinge. Between a two-row widget and a one-row one, the single row pairs with the top row, and the bottom row flips from or to blank.
- **Images, gifs and background effects** have no characters to find, so they're cut into character-width strips that flip the same way.
- **Borders stay put.** A bordered widget's ring doesn't flip. The new section's border takes over halfway through, while the characters are still clattering.
- **Backgrounds and cross-scale sections.** Both messages share the panel for the whole transition, so the new section's `bg_color` arrives at the closing cut and its scale on the final frame. `flair.laser` and `flair.blinds` have the same limitation.
- **Smallsign.** At 16 rows each half-flap is only a few LEDs tall. It works, but it reads best on the bigsign.

### `flair.sand` (flair >= 0.22.0, core >= 4.33)

`flair.sand` turns the outgoing content into sand. Every lit pixel becomes a grain that lets go at its own slightly random moment and falls off the bottom of the panel. Then the incoming content pours in from the top: each of its grains drops straight down and stops on its own pixel, the bottom rows landing first, until the new content is built. Text, borders and backgrounds all turn to sand. It works on every widget type, because the content is snapshotted as pixels rather than text. There is one variant, `flair.sand`.

| `seed` | none    | An int makes the crumble and pour identical on every run; unset gives a fresh pattern each time. |

#### Behavior notes

- **Black content doesn't turn to sand.** Like the other snapshot transitions, only non-black pixels become grains, so black text on a coloured section `bg_color` disappears at the start and the incoming content cuts in at the end. Use a non-black ink, or a widget-level background (for example `top_bg_color` on [`two_row`](/widgets/two_row/)), which does turn to sand.
- **Each real LED is a grain.** On a scaled sign (the bigsign at `default_scale = 4`) the 16 LEDs of a logical pixel fall separately, so the sand is fine-grained at any scale.
- **Animated backgrounds freeze.** A widget's animated `background` is captured as one still frame and crumbles from there.
- **Backgrounds and cross-scale sections.** The first half crumbles the outgoing content over its own `bg_color`; the second half pours the incoming content over the incoming `bg_color`, at the incoming scale, so a cross-scale section arrives at its native size.
